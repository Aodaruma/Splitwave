# EQ controls

New EQ nodes use eight fixed shapes: low cut, low shelf, four Bell bands, high shelf, and high cut. Cuts and shelves start disabled; the four Bell bands start enabled at 0 dB, producing a flat response. Filter shapes are shown as icons; each band has frequency, applicable gain, Q, and enable controls inline. Cuts use 12 dB/octave slopes.

Drag a numbered point horizontally for logarithmic frequency and vertically for gain. Select a band to edit the circular knobs or numeric inputs. Shift makes pointer and arrow-key adjustments finer. Arrow keys move a point; Home or double-click resets its frequency, gain and Q. Knob arrows adjust the value, Enter or double-click resets it, and Home/End select its bounds. Cut filters retain their saved gain but do not use it; their gain control is hidden. Q controls shelf/cut resonance as well as Bell bandwidth. Disabled bands are gray and remain selectable, but their parameters cannot be edited until enabled. Effect bypass disables the parameter area. Controls isolate canvas drag, pan, wheel and keyboard interactions.

Bands have individual colors shared by their points, selectors and compact parameter knobs. Alt+vertical drag on a point or Alt+Up/Down changes only Q, keeping frequency and gain fixed. An enabled Bell band shows its half-gain range; drag anywhere along either vertical boundary to adjust Q horizontally. Boundary arrow keys narrow or widen the band, and Shift gives finer adjustments. The ON/OFF control is on the left of the knob row, with the band reset on the right.

Frequency ticks use uniform line weight and adaptive labels on the points' logarithmic axis. Default and Voice guide strips show approximate listening ranges on that axis. The guide selection is saved with the node as editor data and does not change the response. Reset curve and the guide dropdown sit alongside the preset and EQ mode label.

## Compatibility

- `NodeKind::Eq` remains unchanged. Missing `mode` means `graphic`, in Rust, pipeline loading and preset loading. `gainsDb[10]` always means the original sequential LR4 crossover gains, never parametric peaks.
- Pipeline schema 3 adds explicit legacy mode and the inactive parametric defaults. Older builds with future-version protection will not open these pipelines. Existing factory and user EQ presets retain the graphic algorithm; old EQ presets are not discarded merely for lacking a preset version. Preset recall preserves the node's bypass state.
- Legacy graphic mode uses fixed graph points and a gain knob. Its steady-state audio, including the original phase interaction, is preserved. The displayed response includes that phase; zero graphic gains do not imply a magnitude-flat ten-band sum.
- Saved arbitrary parametric shapes also remain unchanged, including original defaults when fields are absent. Compatibility views display the saved shapes without a shape or mode selector. Applying an existing preset recalls its original algorithm and parameters. Both parameter sets remain saved.
- "Reset curve" restores the fixed eight-band defaults (1 low cut, 2 low shelf, 3–6 Bell, 7 high shelf, 8 high cut); it is not an equivalent sound conversion for a compatibility EQ. Undo restores the previous settings. The adjacent Default / Voice dropdown only changes the frequency guide.

## DSP and limits

Parametric sections use the RBJ cookbook's Q form, including shelving resonance. The existing biquad supports double precision for these sections so low-frequency poles remain accurate at high sample rates; the legacy path keeps its original f32 processing. Frequency is stored in 20–20,000 Hz, gain in ±18 dB, and Q in 0.1–12. Deserialization enforces exactly eight bands and ten legacy gains; graph construction and live updates reject nonfinite or out-of-range values.

The effective parametric frequency is capped at `min(20,000, sampleRate * 0.49)`. The UI displays that limit without changing saved values until edited. The response is the target steady-state response, calculated from the DSP's digital coefficients; during a transition audio approaches that target. An empty `update_effect` patch returns the running EQ's processing rate (or null when inactive), allowing the UI to use the actual rate of a recording/network output. The UI refreshes it once per second and on parameter edits. Legacy graphic mode rejects processing rates at or below 22,628 Hz because its highest crossover would exceed Nyquist. Graph validation checks numeric parameters independently of the pipeline default rate; `build_output_graph` checks Nyquist at the worker's actual processing rate. A 48 kHz recording can therefore use graphic EQ with a 16 kHz pipeline default. A shared EQ is validated and updated at its owning worker's rate; fanout consumers resample the processed audio without constructing another EQ.

Only mode and processing-rate changes rebuild the effect. All band values, shape and enable changes use the existing atomic control path. Parametric updates crossfade two preallocated, fixed-coefficient chains over 20 ms. Unchanged bands retain their exact state. Nearby retunes reconstruct the new transposed biquad state from the last two inputs and outputs, preserving resonant history without copying coefficient-dependent delay coordinates. History is retained only for the same filter and enable state, gain changes of at most 0.5 dB, and changes of at most 10% of the smaller value in each denominator margin (`1+a1+a2`, `1-a1+a2`, `1-a2`). These margins distinguish small pole changes near DC and Nyquist, where absolute coefficient differences can be misleading. Larger changes start the target band at zero state to avoid amplifying incompatible history; their settling still depends on frequency and Q. Each chain uses fixed coefficients, and the destination uses the exact target coefficients without interpolation or per-sample coefficient calculation.

A fade completes before accepting the latest target, preventing continuous drags from repeatedly restarting a fade. Graphic gains use a 10 ms one-pole smoother. The callback performs bounded loops and arithmetic without allocating, locking or calling IPC. Effect bypass uses the existing graph bypass control.

## Checks

Run `bun test tests/eq.test.ts`, `bun run check`, `cargo check` from `src-tauri`, and `cargo test --lib audio::effects::eq::tests`. `cargo test --lib audio::pipeline::dag::tests::eq_validation` covers recording rates, shared controls and live validation without opening devices or files. `cargo test --lib audio::pipeline::sig::tests` checks reconcile classification. `bun run generate --lib export_bindings` regenerates the TypeScript schema through ts-rs without running unrelated audio tests.

The shared response fixtures are checked by TypeScript math and Rust coefficients/audio measurements. DSP tests cover flat/disabled bands, Bell gain/frequency/Q, shelf and cut response, bounds and stable poles at 8–384 kHz, rapid updates, transition step size/convergence, legacy sample equality, bypass/control reuse, and mode/rate rebuilds. Audio paths are platform independent; native device playback and UI interaction still require per-platform testing.

The low-frequency continuity regression settles a 40 Hz sine through a 40 Hz/Q12/+18 dB Bell for three seconds at 48 kHz, changes gain to +17.9 dB, and measures RMS over 25–50 ms. The measured gain is 17.986914 dB (the zero-state transition measured 5.570021 dB); the test also checks convergence to the exact target response. Near-retune bounds cover all five filters at 8/48/384 kHz, frequency and Q changes of 2% and gain changes of 0.5 dB at parameter bounds. Over 250 ms, the quadrature envelope stays within 15% of the range spanned by independently warmed endpoint filters. Large frequency/Q/gain/filter/enable changes in both directions, including 20 kHz to 20 Hz, keep peak amplitude below 0.15 for a 0.01 input (measured maximum 0.12).
